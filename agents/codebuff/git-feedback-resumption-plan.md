Title: Git-Based User Feedback and Workflow Resumption

Objective
- Enable user feedback collection via GitHub PR comments
- Support workflow resumption from Git branch state after Dagger process termination
- Maintain stateless Dagger execution while preserving workflow continuity

Core Strategy: Git Branch + PR Comments Pattern

1) Pre-Feedback Workflow (Create Working Branch + Draft PR)
- Before requesting feedback, orchestrator creates a working branch:
  - Branch name: feature/{task-slug}-{timestamp} (e.g., feature/user-profiles-20250126-143022)
  - Commit current progress with structured message including phase and context
  - Push branch to origin
- Create draft PR with:
  - Title: "[DRAFT] {feature_task_description}"
  - Body: Structured template with current phase, progress summary, and specific feedback request
  - Labels: "feedback-requested", "orchestrator", current phase

2) Feedback Collection via PR Comments
- User reviews branch/PR and provides feedback via comments:
  - @orchestrator approve - continue with current plan
  - @orchestrator modify {instructions} - adjust approach before continuing
  - @orchestrator cancel - abort workflow
  - @orchestrator add-files src/auth.py src/utils.py - modify file selection
  - @orchestrator revise-plan {changes} - update implementation plan
- Structured comment parsing:
  - Command: @orchestrator {action}
  - Context: current phase determines valid actions
  - Parameters: free-form text after action

3) Workflow Resumption (Branch-Based State Recovery)
- When restarting orchestrator, check for existing working branches:
  - Read latest commit message for embedded phase/state JSON
  - Parse PR body for context and feedback requests
  - Scan PR comments for latest user feedback
- Resume from exact point:
  - Load OrchestrationState from commit message metadata
  - Apply any user feedback from PR comments
  - Continue workflow from current phase

4) Branch State Persistence
- Embed workflow state in Git commit messages:
  ```
  feat: implement user profiles [PHASE:PLANNING]
  
  {"phase": "PLANNING", "step": 3, "task_id": "abc123", "files_selected": ["src/auth.py"], "feedback_requested": "approve-plan"}
  
  Generated with Orchestrator 🤖
  ```
- Use .codebuff-state files committed to branch:
  - current_phase.json: {phase, step, context, timestamp}
  - task_spec.json: original task definition
  - exploration_results.json: codebase analysis
  - selected_files.json: file selection with scores
  - implementation_plan.json: detailed plan
  - user_feedback.json: parsed PR comments

5) PR Body Template for Feedback
```markdown
# [DRAFT] Add User Profile Management

## Orchestrator Progress
- **Phase**: Planning
- **Task ID**: abc123-def456
- **Files Selected**: 8 files
- **Branch**: feature/user-profiles-20250126-143022

## Current Status
Implementation plan created with 4 steps:
1. Review selected files and understand current implementation ✅
2. Implement main functionality based on task requirements 🔄
3. Write or update unit tests for new functionality ⏳
4. Update relevant documentation and cleanup ⏳

## Feedback Requested
**Review implementation plan and approve to proceed**

Selected files:
- src/auth/models.py
- src/auth/routes.py
- src/users/profile.py

## Commands
- `@orchestrator approve` - Continue with current plan
- `@orchestrator modify {instructions}` - Adjust approach
- `@orchestrator add-files {paths}` - Add files to selection
- `@orchestrator revise-plan {changes}` - Update plan
- `@orchestrator cancel` - Abort workflow

---
*Generated by Orchestrator Agent - [View State](.codebuff-state/)*
```

6) Feedback Processing Tools
- Add to orchestrator agent:
  - request_feedback(question: str, phase: Phase, context: dict) -> str
    - Creates working branch if not exists
    - Commits current state with metadata
    - Creates/updates draft PR with feedback template
    - Returns: "Feedback requested via PR #{pr_number}. Workflow paused."
  - process_pr_feedback(pr_number: int) -> FeedbackResult
    - Fetches latest PR comments
    - Parses @orchestrator commands
    - Returns structured feedback with action and parameters
  - resume_from_branch(branch_name: str) -> OrchestrationState
    - Checks out working branch
    - Loads state from .codebuff-state files
    - Parses commit metadata
    - Returns restored state for continuation

7) Git Integration Enhancement
- Add git utilities to orchestrator tools:
  - create_working_branch(task_slug: str) -> str
  - commit_with_metadata(message: str, metadata: dict) -> str
  - push_branch(branch_name: str) -> str
  - create_draft_pr(title: str, body: str, branch: str) -> int
  - get_pr_comments(pr_number: int) -> list[dict]
- Use GitHub API via agent token for PR operations

8) Resumption Entry Point
- Add new Dagger function: resume_workflow
  ```bash
  dagger call --mod agents/codebuff \
    resume-workflow \
    --branch-name feature/user-profiles-20250126-143022 \
    --github-token env:GITHUB_TOKEN \
    --openai-api-key env:OPENAI_API_KEY
  ```
- Function logic:
  - Clone repo and checkout specified branch
  - Load workflow state from .codebuff-state
  - Check for PR feedback via GitHub API
  - Continue orchestration from saved phase

9) State Validation and Recovery
- Validate state consistency on resumption:
  - Verify .codebuff-state files are complete and parseable
  - Check that container matches expected branch state
  - Validate phase progression rules
- Handle state corruption:
  - Restart from last valid phase if partial corruption
  - Provide clear error messages with recovery options
  - Allow manual state reset via CLI flag

10) Implementation Phases with Feedback Gates
- Natural feedback points:
  - After exploration: "Review {N} files analyzed. Continue?"
  - After file selection: "Selected {N} files. Approve selection?"
  - After planning: "Review {N}-step plan. Proceed with implementation?"
  - After implementation: "Changes complete. Review and approve PR?"
- Each gate:
  - Commits progress to working branch
  - Updates draft PR with current status
  - Waits for user feedback via PR comments
  - Resumes when user provides @orchestrator command

11) Error Handling and Rollback
- If workflow fails after user feedback:
  - Commit error state with debug info
  - Update PR with error summary and suggested fixes
  - Allow resumption with --retry or --rollback flags
- Rollback capabilities:
  - Reset to specific phase: --resume-from-phase PLANNING
  - Discard changes: --reset-branch (force push clean state)

12) Configuration
- Add feedback settings to orchestrator config:
  ```yaml
  orchestrator:
    feedback:
      enabled: true
      github_token_env: GITHUB_TOKEN
      branch_prefix: "feature/orchestrator-"
      pr_template: "path/to/template.md"
      auto_request_gates: ["PLANNING", "IMPLEMENTATION"]
  ```

13) CLI Examples
```bash
# Start workflow (will pause at feedback gates)
dagger call --mod agents/codebuff \
  orchestrate-feature-development \
  --feature-task-description "Add user profiles" \
  --github-token env:GITHUB_TOKEN \
  --openai-api-key env:OPENAI_API_KEY

# Resume from existing branch after feedback
dagger call --mod agents/codebuff \
  resume-workflow \
  --branch-name feature/user-profiles-20250126-143022 \
  --github-token env:GITHUB_TOKEN \
  --openai-api-key env:OPENAI_API_KEY

# Force restart from specific phase
dagger call --mod agents/codebuff \
  resume-workflow \
  --branch-name feature/user-profiles-20250126-143022 \
  --resume-from-phase IMPLEMENTATION \
  --github-token env:GITHUB_TOKEN \
  --openai-api-key env:OPENAI_API_KEY
```

14) Benefits of Git-Based Approach
- Survives Dagger process termination
- Leverages familiar GitHub review workflow
- Provides permanent audit trail
- Enables collaborative feedback (multiple reviewers)
- Integrates with existing CI/CD on branch push
- Supports partial rollback and replay
- Works with GitHub notifications and review assignments
